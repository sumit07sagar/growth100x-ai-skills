# Extracting and applying design DNA

"Make it more like X" is a request for X's design *principles* applied to a different business — not a clone. Extract the DNA, then translate.

## What to codify from a reference (the DNA sheet)

Write these down explicitly before designing — it forces real decisions:

- **Type**: scale ratio (Apple ≈ huge display/small body contrast), families (grotesque? serif accents?), weight usage, letter-spacing habits.
- **Color logic**: base (light/dark/warm), how many accents, where accent is allowed (CTAs only? headings?), gradient usage.
- **Space**: section padding rhythm, content max-width, density (Amazon = dense grid, Apple = one idea per viewport).
- **Layout patterns**: hero style, card treatments, how products/services are presented, nav behavior (sticky? mega-menu? minimal?).
- **Imagery**: photography vs illustration vs 3D vs abstract gradients; treatment (full-bleed, framed, floating with shadow).
- **Motion**: scroll reveals, hover behavior, marquee/ticker, none.
- **Voice**: headline length and tone (Apple: 3-word poetry; Stripe: technical-confident; agency: bold claims + case proof).

If given a URL, fetch it and derive these from what's actually there. If given a brand name, work from its known identity — and when unsure, search for current screenshots rather than guessing from memory.

## Common archetype cheat-sheet

- **Apple-like**: massive type, extreme whitespace, one message per screen, muted neutrals + product imagery, no visual noise, few words. Trap: still needs the client's conversion path — add it elegantly (floating CTA), don't omit it.
- **Amazon/marketplace-like**: information density done deliberately — strong grid, prices and ratings visible, faceted browsing feel, utilitarian type, trust badges. Trap: dense ≠ cluttered; alignment discipline is everything.
- **Stripe/modern SaaS**: gradient accents on dark or off-white, code-adjacent credibility, feature grids with line icons, social proof logos row, generous line-height. 
- **Crypto/fintech-energy**: dark base, glow accents, big numbers/stats, motion (ticker, counters), bold display type. Trap: keep trust anchors (security notes, registrations) or it reads as scam.
- **Premium agency**: oversized editorial type, case-study-led, asymmetric layouts, cursor/hover play, minimal chrome, dark or paper palettes.
- **Local service premium** (clinics, movers, salons): warm trustworthy palette, reviews everywhere, people photography, sticky call/WhatsApp on mobile, service-area clarity, prices or "from ₹" anchors.

## Translation rules

1. DNA sets the *how*, the company sets the *what*: information architecture always comes from the business (its services, its one desired action, its trust assets).
2. Never copy protected assets: no reference-brand logos, product shots, or verbatim copy. Fonts: use free equivalents (Google Fonts) that evoke the same feel — note the pairing chosen.
3. One DNA per site. If the user names two references ("Apple but with Amazon's product grid"), pick the dominant one for the shell and borrow the named component only.
4. State the DNA sheet in one short paragraph when presenting the mockup — it shows intent and makes feedback specific ("less whitespace" beats "something's off").
